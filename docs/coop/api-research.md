# 生協との発注データ連携：調査結果

調査日: 2026-09-22
目的: おうちCO-OP（ユーコープ）に発注用のAPI／データ連携の窓口があるか確認する

## 結論

**公開された連携APIは存在しない。** しかも「ユーコープが未対応」ではなく、
**生協業界として法人向けのデータ発注を提供していない**状態に近い。

## 分かったこと

### 1. おうちCO-OPの法人向け注文経路は3つだけ

注文書・電話・eふれんず（Web）。CSV一括注文もAPI連携も記載なし。
締切は配達日翌々日のAM10時。
出典: https://www.ouchi.coop/lpo/corporate/index.html

### 2. eふれんずはユーコープのシステムではない（重要）

eふれんずは **CWS（Coop-Web-Standard）** という全国共通基盤の上で動いている。
運営は日本生協連／コープ情報システム株式会社。
ドメインも `ouchi.ef.cws.coop` で、`cws.coop` を複数の生協が共有している。

利用している生協:
コープ東北サンネット事業連合、コープ北陸事業連合、CO・OPとやま、
ユーコープ、コープCSネット、コープ九州事業連合 など

**つまり、eふれんずにAPIを付けるかどうかはユーコープ単独では決められない。**
提案先は日本生協連／コープ情報システムのレベルになる。

裏を返せば、実現すれば全国の会員生協に効く。事業規模としては大きい。

出典: https://www.coopis.co.jp/ja/service/system.html

### 3. コープ情報システムの公開情報に外部API・EDIの記載なし

商品受発注システムは持っているが、これは生協が仕入れる側の仕組み。
事業所・法人が発注する側のデータ連携についての記載は見つからない。

### 4. 他の生協も同じ

主要3グループすべてを確認したが、法人向けのデータ発注はどこも提供していない。

| 生協 | 法人向けの注文方法 | 基盤 | 締切 |
|---|---|---|---|
| おうちCO-OP（ユーコープ） | 注文書・電話・eふれんず | CWS（日本生協連の全国共通基盤） | 配達日翌々日 AM10時 |
| コープデリ 法人サービス | eフレンズ・電話 | 自社（weekly.coopdeli.jp） | 配達日翌日 26時 |
| 法人版パルシステム | インターネット・注文用紙 | 自社 | 決まった曜日まで |

CSV一括注文・API連携の記載はいずれにも無い。
**生協業界として、法人顧客向けのデータ発注は提供されていない。**

出典:
- https://www.pal-system.co.jp/service/houjinpal/
- https://efriends.coopdeli.jp/docreq/houjin/index.php

### 4-1. どの生協かで変わること

結論（APIが無い）は変わらないが、**提案先と難易度が変わる**。

- **CWS系（おうちCO-OP、コープCSネット、コープ東北、コープ北陸、CO・OPとやま、コープ九州）**
  → 基盤が全国共通のため、単独の生協では決められない。日本生協連／コープ情報システムの話になる。
  ハードルは高いが、実現すれば全国の会員生協に効く

- **自社基盤（コープデリ、パルシステム）**
  → その連合会が単独で判断できる。**話が通る相手が近い**。
  ただし対象範囲は狭くなる

**まず施設がどの生協と取引しているかを確認すること。** 請求書か配達伝票で分かる。
システムの `suppliers` には「生協」としか登録されておらず、
献立表テンプレートの凡例が「C…おうちCO-OP」になっている。

### 5. eふれんずにあるもの／ないもの

| 機能 | 状況 |
|---|---|
| 注文コードでご注文（コード＋数量をまとめ入力） | **ある**。今の実装はここに貼る前提 |
| 印刷ボタン | ある |
| お気に入り商品 | ある |
| 注文履歴のCSV出力 | ヘルプに記載なし。要問い合わせ |

出典: https://www.ouchi.coop/efriends/help/bb_04.html

### 6. 業界の標準解は別にある

給食業界では、受発注プラットフォームを挟むのが標準的な形になっている。

```
給食管理システム → 発注CSV → 受発注プラットフォーム → 卸
```

- クロスオーダー給食（クロスマート）: 使用日単位・週間単位の発注UI、CSV取込、
  検収表の自動生成。注文はCSVやFTPSで自動受信
- BtoBプラットフォーム受発注（インフォマート）
- 献ダテマン（栄養・給食管理システム）は、クロスオーダー給食向けの
  発注データCSV様式に既に対応している

**生協がこれらに参加しているという情報は見つからなかった。**

ただしクロスオーダー給食には、**未契約の業者にはFAXまたはメールで発注を代行する**
仕組みがある。卸側の対応がなくても発注データを流せる。
出典: https://www.yumekobo.jp/common/pdf/rakukon/xorder_renkei.pdf

## これを踏まえてどうするか

### 短期（実装済み）

生協発注画面で注文コードと数量を出し、eふれんずの「注文コードでご注文」に貼る。
コードは自社DBに持つので、カタログを引き直す手間は消える。

### 中期（要問い合わせ）

ユーコープの事業所担当に聞くべきは、CWSの改修を伴わない2つ:

1. **事業所向け商品リストをExcel/CSVでもらえるか**
   → 営業が使う一覧が既にあるはず。運用で出せる可能性が高い
2. **注文履歴のCSV出力ができるか**
   → eふれんず（CWS）の機能なので、こちらは改修が要るかもしれない

### 長期（提案するならこの形）

「APIを作ってください」ではなく、
**「既存の受発注プラットフォームに乗っていただけないか」** を提案する。

生協側の負担がまったく違う。前者は自社開発、後者は既存サービスへの参加。
こちらは標準様式のCSVを出すだけでよく、生協が画面を変えても壊れない。

献ダテマンが既にこの形を取っているので、前例として示せる。

## やらないと決めたこと

**eふれんずの画面自動操作。**

生協の品目は数十で週1回、手で貼れば1〜2分。
他社サイトの画面構造に依存する仕組みを持つと、生協が画面を変えるたびに直す
義務が残り、壊れたことに気づくのは発注が通らなかった後になる。
削減できる手間より保守の負担のほうが大きい。
